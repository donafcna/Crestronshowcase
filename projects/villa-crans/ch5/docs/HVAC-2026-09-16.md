# HVAC — marche, arrêt et ventilation, version source 1.0.179

Demande explicite de Donatien : mêmes commandes sur dalle, tablette, XPanel et iPhone, avec contrat JSON, SIMPL# Pro slot 1 et signaux SIMPL Windows slot 2 visibles au Debugger.

## Contrat v4 conservé

Les boutons sont déclarés dans les deux HTML avant initialisation CH5. Leur sélection vient de `receiveStateSelected`, sans état actif fabriqué dans le DOM. `contrat.cvcEtendu` décrit l'extension ; chaque `pieces[].pilotages.cvc` contient marche/arrêt, vitesses et état initial. Les pièces désactivées et les services CVC désactivés dans la configuration réelle restent désactivés. La configuration showcase possède sa propre architecture de démonstration.

| Commande GUI | Join digital | Signal reçu par SIMPL slot 2 |
|---|---:|---|
| ON | 610 | `HVAC_On_Cmd` |
| OFF | 611 | `HVAC_Off_Cmd` |
| AUTO | 612 | `HVAC_Fan_Auto_Cmd` |
| Vitesse 1 | 613 | `HVAC_Fan_Low_Cmd` |
| Vitesse 2 | 614 | `HVAC_Fan_Medium_Cmd` |
| Vitesse 3 | 615 | `HVAC_Fan_High_Cmd` |

Analogique GUI **61** : 0 Auto, 1 faible, 2 moyenne, 3 forte. Les autres valeurs sont rejetées. Les six retours digitaux utilisent les mêmes joins côté GUI, avec un seul état ON/OFF et une seule vitesse sélectionnés. OFF conserve la vitesse choisie pour le prochain ON.

Le slot 1 écrit la pièce du panel d'origine sur **a10 avant la commande HVAC**. Les sorties globales EISC 610–615 sont exclusivement des impulsions : le feedback maintenu n'écrase jamais ces impulsions. Les retours propres à chaque pièce sont séparés, ce qui évite qu'un panel affichant une autre pièce récupère le mauvais état.

## Retours et cibles propres à chaque pièce

Base `b = 1000 + (id − 1) × 100`. Le bloc CVC réduit déjà présent est complété, sans réactiver les blocs GUI v3.

| Join EISC | Sens côté symbole SIMPL | Nom / sens |
|---|---|---|
| d(b+93) | sortie | `Rxx_HVAC_On_fb` : état marche tenu par C# |
| d(b+94) | sortie | `Rxx_HVAC_Off_fb` : inverse |
| d(b+95..98) | sorties | `Rxx_HVAC_Fan_Auto/Low/Medium/High_fb` |
| a(b+33) | sortie | `Rxx_HVAC_FanSpeed_fb#` : vitesse demandée/confirmée |
| d(b+93) | entrée | `Rxx_HVAC_On_Actual` : état réel, **vrai et faux sont traités** |
| a(b+33) | entrée | `Rxx_HVAC_FanSpeed_Actual#` : vitesse réelle 0..3 |

Les offsets digitaux d'alarme +81..92 et l'analogique +32 de température mesurée restent inchangés. Les noms `_Cmd` / `_Actual` de cette extension désignent leur rôle explicitement ; les conventions historiques d'autres familles ne sont pas renommées.

Comme pour les commandes existantes, C# tient un état de commande initial. Dès que le driver transmet un retour physique `_Actual`, celui-ci met à jour l'état et les panels affichant cette pièce. **Un bouton sélectionné ne prouve pas à lui seul que la cassette réelle a démarré** : raccorder les retours du driver pour cette confirmation.

## Exemple Debugger : Home cinéma, pièce 8

1. Sélectionner pièce 8 : a10 (`Room_Selected#` en sortie du symbole) doit indiquer 8.
2. ON/OFF : impulsions `HVAC_On_Cmd` / `HVAC_Off_Cmd` ; états `R08_HVAC_On_fb` / `Off_fb` sur d1793/1794.
3. Vitesses : impulsions 612–615 ; a1733 (`R08_HVAC_FanSpeed_fb#`) vaut 0, 1, 2 ou 3.
4. Retour driver : faire varier `R08_HVAC_On_Actual` sur les deux fronts et `R08_HVAC_FanSpeed_Actual#` ; les panels de la pièce 8 doivent suivre. Un panel de la pièce 7 doit conserver son état.
5. Passer sur une autre pièce puis revenir : marche et ventilation de la pièce 8 doivent être conservées.
